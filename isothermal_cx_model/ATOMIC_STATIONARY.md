# Атомная модель: этап 2, согласованный стационарный поиск

Этап добавляет ионизацию в локальный/мультистартовый поиск theta,j_t и его
команду запуска. Пробные уравнения первого этапа не меняются. Массовые сканы,
автоматическая карта стартов и удаление исторических решателей в этот коммит
НЕ входят. Имена stationary и run_stationary пока сохранены,
но используют единственную реализацию IVP в transport.

## API и численная область

```python
from isothermal_cx_model.ionization import make_ionization_coefficients
from isothermal_cx_model.stationary import solve_stationary

outcome = solve_stationary(theta_guess, j_guess, p['beta'], D, p['lambda_sh'], geometry,
    E_exc=E_exc, rr=rr, ionization=make_ionization_coefficients(p, scale=1),
    inlet_momentum=inlet)
if outcome['status'] == 'converged':
    solution = outcome['solution']
```

p,D,E_exc,rr,inlet,geometry создаются прежними фабриками. Python API принимает
безразмерную theta; CLI --guess принимает температуру в эВ и j_t=J(L)/J0.
Необязательная ionization=(0,0) сохраняет прежнюю физику. Разрешена функция
theta -> (D_ion,E_ion). Пара передаётся в КАЖДЫЙ пробный расчёт: разностный
якобиан, уменьшение шага, повторную корректировку и свежий проверочный профиль.

Координаты поиска прежние: log(theta),log(j_t). Искусственный потолок j_t=1
снят, в том числе для пробных точек до согласования корня. Шаг может пересекать
j_t=1 в обе стороны. j_min>0 и необязательный j_max>j_min задают численное
окно; j_max=None по умолчанию означает отсутствие пользовательского потолка
(кроме конечной представимости float64). j_min тоже может быть больше единицы.
Это не физические ограничения. Диагностика сохраняет заданные границы.

Условие lambda*theta*j_t<1 и допустимость дозвукового старта проверяет сам IVP.
Недопустимые интегрирования не заменяются фиктивными штрафами или нулями.
Поиск остаётся локальным: неуспех старта или окна не доказывает отсутствие корня.

Как и прежде, alpha находится по omega(alpha)=1; корректируются одновременно
R_J=j(alpha)-1 и R_M=mu(alpha)-G(alpha). Успех требует повторной корректировки
с более строгими допусками, свежего интегрирования, всех входных условий,
дозвукового входа и независимых балансов. Одна только метка energy_matched
не является решением полной краевой задачи.

## Запуск

Из корня проекта, с физической ионизацией в полном объёме:

```powershell
python -B -m isothermal_cx_model.run_stationary --density 1e15 --lambda-sh 7 --ionization-scale 1 --guess 20 8 --points 8000 --no-show --output atomic_hot_root
```

Начальное приближение 20 эВ, j_t=8 не является найденным решением; данный
локальный поиск при текущем источнике приходит к другому состоянию. Физические
параметры и масштабы читаются из прежнего cx_config.json, JSON не изменяется.
Нужно выбрать новую или пустую папку --output: старые результаты не затираются.

По умолчанию --ionization-scale 0, то есть старые команды НЕ меняют физику
незаметно. Полное включение требует явного --ionization-scale 1. Значения
между 0 и 1 полезны для проверки/продолжения по параметру, но не заменяют
физический коэффициент. Один множитель действует и на рождение частиц, и на
потерю энергии ионизации. Есть --j-min и необязательный --j-max.

Несколько --guess по-прежнему дают мультистарт с объединением близких корней,
а не автоматическую гарантию полноты, уникальности или устойчивости.

## Вывод и смысл счётчиков

В solutions.json добавлены schema_version=2, ionization_scale, j_max,
коэффициенты D_ion,E_ion в каждом корне. Сохранены исходные настройки, невязки,
контроль точности и все интегральные балансы. В NPZ сохранены также множитель
ионизации и её два коэффициента. График J/J0 больше не обрезается на 1.05:
показан весь профиль, включая внутренний максимум и J>J0.

В локальном solutions.json поле recombined_fraction заменено на:

- net_particle_loss_fraction = 1-j_t (может быть отрицательным);
- recombination_count_per_inlet = integral A*S_RR dz / J0;
- ionization_count_per_inlet = integral A*S_ion dz / J0.

Последние два счётчика не являются взаимоисключающими долями одних и тех же
частиц: в модели возможны повторные циклы ионизации/рекомбинации. Их разность
совпадает с j_t-1 с точностью входной невязки и квадратуры. В balances старое
имя particle_loss_integral остаётся псевдонимом ТОЛЬКО числа рекомбинаций.
Внешним читателям локального solutions.json следует учитывать новую схему.
Пакетные CSV тоже обновлены до версии 2; см. RR_LAMBDA_SCAN.md.

## Контрольные результаты и предел интерпретации

При текущем источнике, n0=1e15 см^-3, lambda=7, K=500, кинетическом входе,
CX(T,0), возбуждении, RR и ионизации с единичными множителями:

| Старт: T, j_t | Найденная T, эВ | a, см | j_t |
| --- | ---: | ---: | ---: |
| 0.13, 0.8 | 0.119194928968 | 164.993436263 | 0.775561375634 |
| 20, 8 | 96.1704570832 | 184.422155247 | 1.60179494169 |

Для горячего корня на 8000 точках ошибки балансов частиц, импульса и энергии
около 5.1e-8, 8.5e-11 и 3.0e-9 от J0,M0,W0. Нормированное число ионизаций
около 0.60179489, рекомбинаций около 8.0e-12. Это проверки решения уравнений,
не оценка их физической применимости. В частности, L-a около 0.07785 см
(0.78 мм): применимость гидродинамики и изотермичности в таком тонком слое
нужно исследовать отдельно. На холодном корне прямая ионизация экспоненциально
мала. Эти два старта НЕ устанавливают число всех корней и их устойчивость.

Независимый аналитический тест: A=const, только ионизация, beta=0.5,
lambda=5, D_ion=1, E_ion=0.2, G(alpha)=1. Сохраняются mu=1 и
omega+0.2*j=1.2. Из j_a=1 и звукового выхода j_t=1/b следует

    lambda*b^2/(8*beta) - (1+epsilon)*b + epsilon = 0, epsilon=0.2.

Оба аналитических корня с j_t>1 находятся численным поиском из неточных
стартов; проверяется также независимая формула alpha и все ГУ. Это контрольные
математические задачи, не отдельные прогнозы для ГДЛ.
