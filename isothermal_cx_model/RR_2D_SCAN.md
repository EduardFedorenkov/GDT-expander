# Автоматический двумерный поиск стационарных решений

Этот скрипт использует уже установленный `stationary_recombination.py`.
Физика, IVP и проверка корней не меняются. Ручное `--guess` **не требуется**.
Старый `run_recombination` остаётся самостоятельным локальным решателем.

После этапа atomic trial его IVP находится в `solver_atomic.py`, но ионизация
в этом глобальном поиске пока выключена. Флаг нового пробного примера
`--ionization-scale` к этому сканеру ещё не подключён. См. `ATOMIC_TRIAL.md`.

## Запуск

Из корня проекта:

```powershell
python -B -m isothermal_cx_model.scan_recombination --no-show --output rr_map_01
```

Параметры источника, нейтральная плотность и lambda читаются из существующего
`simple_cx_model/cx_config.json`. Ни JSON, ни прежние результаты не изменяются.
Папка `--output` должна быть новой или пустой.

Контрольный случай с изменением только n0 и lambda в памяти:

```powershell
python -B -m isothermal_cx_model.scan_recombination --density 1e15 --lambda-sh 7 --temperature-min .01 --temperature-max 100 --temperature-count 55 --j-count 60 --no-show --output rr_map_control
```

Только построить карту, без уточнения корней:

```powershell
python -B -m isothermal_cx_model.scan_recombination --map-only --no-show --output rr_map_only
```

`--no-show` сохраняет рисунок без открытия окна. Если убрать этот флаг,
изображение также откроется после расчёта.

## Что рассчитывается

1. В каждом узле `(T,j_t)` запускается прежний пробный решатель: интегрирование
   от плазмаприёмника до события `omega=1`, которое определяет `alpha`.
2. Только при наличии обеих входных невязок вычисляются `R_J=j_a-1` и
   `R_M=mu_a-mu_in(alpha)`. Значение `energy_matched` ещё НЕ означает корень.
3. Для автоматических стартов используются допустимые углы ячеек, в которых
   обе невязки меняют знак, затем локальные минимумы общей невязки и другие
   узлы с небольшой невязкой. Знак на углах — лишь эвристика, не доказательство
   пересечения нулевых линий внутри ячейки.
4. До `--max-starts` точек передаются прежнему стационарному решателю.
   Он выполняет локальное уточнение, повторный расчёт с более строгой
   точностью и проверки трёх интегральных балансов. Дубликаты корней удаляются
   по параметрам, а не по меткам формы профиля.

Можно дополнительно указать несколько ручных `--guess T_eV j_t`, например для
сравнения с предыдущим локальным расчётом. Они добавляются к автоматическим
стартам, не заменяя их. Все старты и результаты попыток записываются в JSON.
У каждого старта есть `start_id`; у попытки `converged_to` явно указывает,
к какому `root_...` она сошлась (либо null при отсутствии проверенного корня).
Дополнительные ручные старты должны лежать внутри диапазона карты.

## Как читать рисунок

Три панели показывают:

- знаковую нормированную невязку частиц;
- знаковую нормированную невязку импульса;
- логарифм общей невязки локального решателя:
  `log10(max(abs(log(j_a)), abs(log(mu_a/mu_in))))`.

Для цвета первых двух панелей используется положительная нормировка
`R_J/(1+max(abs(j_a),1))` и `R_M/(1+max(abs(mu_a),abs(mu_in)))`.
Она не меняет знаки и нули. Третья панель использует именно ту норму, по
которой работает локальный решатель; минимум цвета сам по себе не есть корень.

Чёрная сплошная линия — `R_J=0`, оранжевая пунктирная — `R_M=0`.
Пустые розовые кружки — выбранные старты. Зелёные звёзды — только проверенные
корни. Тонкие красные линии на третьей панели соединяют принятые итерации
численного метода: это НЕ траектории плазмы и НЕ карта бассейнов притяжения.

Серый фон означает, что совместные невязки в узле не определены. Причина
хранится в массиве `status`: например, возврат к звуку, выход из области
геометрии, неприменимость кинетической границы или численная неудача.
Через ячейку с недопустимым углом нулевые контуры не проводятся.
Цветовые плитки отображают выборку узлов, а не доказанную непрерывную область.

По умолчанию ось Y — `1-j_t`, с логарифмической частью и малой линейной
областью у нуля. Это позволяет одновременно видеть холодные корни и горячие
корни с `j_t` почти равным единице, включая точную границу `j_t=1`.
В произвольной пробной точке `1-j_t` — координата заданного потока;
долей рекомбинировавших входных частиц она становится только на корне.

Для обычной оси `j_t` используйте `--j-axis linear` или `--j-axis log`.
Ось T всегда логарифмическая, температура задаётся в эВ.

## Сетка, масштабирование и проверка разрешения

По умолчанию T меняется от .001 до 100 эВ по 45 логарифмическим узлам.
Смешанная сетка j_t охватывает малые j_t и отдельно разрешает `1-j_t`
до порядка 1e-12. Параметр `--j-count` задаёт приблизительное число узлов
после объединения подсеток; точная форма сохраняется в NPZ.

Доступны `--temperature-min`, `--temperature-max`, `--temperature-count`,
`--j-min`, `--j-max`, `--j-count` и `--j-grid mixed|linear|log`.
Для узкого участка около холодного корня полезна линейная сетка j_t:

```powershell
python -B -m isothermal_cx_model.scan_recombination --density 1e15 --lambda-sh 7 --temperature-min .08 --temperature-max .17 --temperature-count 25 --j-min .65 --j-max .9 --j-count 25 --j-grid linear --j-axis linear --max-starts 4 --no-show --output rr_cold_zoom
```

Границы T ограничивают и локальное уточнение. `j_min` также служит нижней
границей уточнения, но `j_max` ограничивает ТОЛЬКО сетку: существующий локальный
решатель допускает движение до j_t=1. Выход корня за верхнюю границу карты
помечается `outside_scan_j_range` в отчёте; тогда расширьте карту.

Ни один конечный скан не гарантирует нахождение всех корней: возможны узкие
допустимые полосы, касания нулевых линий и корни между узлами. Для проверки
нужно увеличивать плотность сетки, число стартов, строить локальные карты
и сравнивать параметры уже уточнённых корней. Пустой поиск не доказывает
отсутствия решений, а найденные решения не доказывают их устойчивости.

## Результаты и API

`residuals.png` — изображение карты с корнями и стартами.
`residuals.npz` — T, theta, j_t, невязки, alpha, общая норма, valid и status.
Ориентация двумерных массивов — `(n_j,n_T)`. Нет объектов/pickle:

```python
import numpy as np
with np.load('rr_map_01/residuals.npz', allow_pickle=False) as data:
    T = data['T_eV']
    jt = data['j_target']
    R_J = data['R_J']  # R_J[j_index,T_index]
```

`summary.json` — параметры, статусы узлов, выбранные старты, истории локальных
попыток, проверенные корни и погрешности балансов. Сетка, первый отчёт и
рисунок сохраняются ДО уточнения; их можно изучить даже при прерывании
дальнейшего поиска. `root_001_profiles.npz` и аналогичные файлы — профили
проверенных корней с переменным потоком J.

Функции доступны из `recombination_map.py`: `make_j_grid`, `scan_residuals`,
`candidate_cells`, `choose_starts`, `plot_residuals`. На вход API температура
подаётся как theta, в отличие от CLI, где она задаётся в эВ.

Сохраняются флаги геометрии, модели входного импульса, постоянного/температурного
CX и множителей RR/возбуждения. При RR используется прежняя Case A модель;
ионизация, трёхчастичная рекомбинация и другие новые процессы не добавляются.

Код выхода: 0 — построена карта `--map-only` или найден хотя бы один проверенный
корень; 1 — из выбранных стартов корни не найдены; 2 — ошибка аргументов.
Тесты: `python -B -m unittest discover -s tests -p test_recombination_map.py -v`.
