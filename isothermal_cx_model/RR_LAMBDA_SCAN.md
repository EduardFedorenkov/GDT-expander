# Скан по lambda_sh и n0 для атомной модели

Новый запуск: `python -m isothermal_cx_model.scan_lambda`.
`scan_lambda.py` — актуальная точка входа; общий пакетный код находится в parameter_scan.py.
Требуется уже установленный автоматический `scan_stationary.py`.
В CLI прямая ионизация включена по умолчанию (--ionization-scale 1).
Для предела без ионизации используйте --ionization-scale 0.
Исторический суффикс recombination в выходных CSV сохранён для совместимости;
он не ограничивает набор процессов. Формат пакетных CSV имеет версию 2.

## Принцип

Для КАЖДОЙ пары `(lambda_sh,n0)` запускается существующий сканер
`scan_stationary` в отдельном процессе того же Python:

1. Полная заданная сетка `(T,j_t)` и карта двух невязок.
2. Автоматический выбор стартов, без обязательного `--guess`.
3. Прежнее локальное уточнение и строгая проверка стационарных корней,
   включая интегральные балансы частиц, импульса и энергии.
4. Сохранение всех найденных различных корней этой пары в общую таблицу.

Это не отдельный физический решатель и не поиск только продолжением корней
с предыдущей плотности. Уравнения, коэффициенты, правила допустимости,
критерии проверки и удаление дубликатов остаются прежними.
Во внешнем скане корни разных физических пар никогда не объединяются.
Обвязка дополнительно проверяет режим ионизации, исходные масштабы, входные
невязки, три баланса и согласованность новых коэффициентов/счётчиков в отчёте.

## Запуск

Из корня проекта. Сначала разумно проверить одну физическую пару:

```powershell
python -B -m isothermal_cx_model.scan_lambda --ionization-scale 0 --lambdas 7 --densities 1e15 --no-show --output rr_lambda_test
```

Для перехода к полной ионизации замените в этой команде --ionization-scale 0 на 1 и выберите
НОВУЮ папку --output. Коэффициенты ионизации и её энергетической цены
пересчитываются при n0 каждой физической пары и температуре каждого корня.

Короткая проверенная задача: четыре пары, только окно горячего корня,
без ручных стартов (196 узлов карты плюс уточнения):

```powershell
python -B -m isothermal_cx_model.scan_lambda --lambdas 7 7.1 --densities 9e14 1e15 --ionization-scale 1 --temperature-min 80 --temperature-max 110 --temperature-count 7 --j-min 1.35 --j-max 1.9 --j-count 7 --j-grid linear --j-axis linear --max-starts 2 --points 4000 --no-show --output atomic_lambda_hot_test
```

При текущем источнике найдены:

| lambda | n0, см^-3 | T, эВ | a, см | j_t |
| ---: | ---: | ---: | ---: | ---: |
| 7 | 9e14 | 96.1557117 | 184.4134904 | 1.60200815 |
| 7 | 1e15 | 96.1704571 | 184.4221552 | 1.60179494 |
| 7.1 | 9e14 | 93.5522951 | 184.4127734 | 1.62291237 |
| 7.1 | 1e15 | 93.5667759 | 184.4215099 | 1.62269368 |

Это проверка согласованного численного решения, не всей области параметров
и не физической применимости тонкого гидродинамического слоя. Холодный корень
в выбранное температурное окно заведомо не входит. Достоверность гидродинамики,
изотермичности и заданного нейтрального фона исследуется отдельно.

Несколько lambda и логарифмическая сетка нейтралов:

```powershell
python -B -m isothermal_cx_model.scan_lambda --ionization-scale 0 --lambdas 5 7 9 --n0-min 1e12 --n0-max 1e15 --n0-count 7 --no-show --output rr_lambda_results
```

Можно задавать явные `--densities 1e14 3e14 1e15`, как и явные `--lambdas`.
Для широкого скана с ионизацией добавьте --ionization-scale 1, задайте достаточное
окно температуры и положительного j_t. Например, --temperature-max 150 --j-max 10
--j-axis log. Такой выбор окна не гарантирует нахождения всех корней; сначала
разумно проверить отдельные пары картами, затем увеличивать число узлов и стартов.
Альтернатива — `--lambda-min`, `--lambda-max`, `--lambda-count`.
При count=1 задайте равные границы либо явный список с одним элементом.
Дубликаты значений удаляются, пары обходятся в порядке возрастания lambda и n0.

По умолчанию: lambda от 5 до 9 (5 значений), n0 от 1e12 до 1e15 (7 значений),
температура .001–100 эВ (45 узлов), смешанная сетка j_t (около 48 узлов).
Это примерно 75600 пробных IVP плюс уточнение корней — существенно дороже
старого скана! Количество пар и пробных задач печатается до начала расчёта.
Полный большой диапазон автоматически при тестировании патча не запускался.

Внутренние настройки совпадают с новым 2D-сканером:
`--temperature-min/max/count`, `--j-min/max/count`, `--j-grid`, `--j-axis`,
`--max-starts`, `--iterations`, `--points`, `--residual-tol`, `--balance-tol`.
Есть прежние флаги геометрии `--geometry` или `--K`, и `--inlet-momentum`.

По умолчанию используются `--cx-mode temperature`, `--rr-scale 1` и
`--excitation-scale 1`: то есть D(theta), RR и возбуждение включены.
--ionization-scale 0 сохраняет прежнюю физику; 1 включает полный коэффициент,
а промежуточный множитель служит численному исследованию/продолжению по процессу.
Один и тот же множитель применяется к рождению частиц и к цене ионизации.
Если --j-max не указан, выбирается 1 без ионизации и 10 при положительном
множителе, как в одиночном сканере. j_t>1 разрешён, а смешанная сетка разрешает
окрестность единицы с двух сторон. j_max ограничивает карту, не локальное
уточнение; вышедший за карту корень помечается outside_scan_j_range.
`--cx-mode constant` берёт k_cx из JSON. При изменении n0 пересчитываются
CX, возбуждение и ионизация. Коэффициенты RR зависят от температуры и масштабов
источника, но не приобретают искусственную зависимость от нейтралов.
В CSV D, E_exc, R_rr, Q_rr, D_ion, E_ion записаны при температуре КАЖДОГО корня.

Python API:

```python
roots, grid = scan_lambda_neutral(lambdas, densities, config_path, output,
    geometry=geometry, ionization_scale=1., scan_arguments=inner_arguments,
    resume=False)
```

ionization_scale — отдельная настройка: в низкоуровневом API по умолчанию 0,
в CLI scan_lambda — 1.
Не передавайте --ionization-scale через scan_arguments: повторное назначение
или сокращённый псевдоним этого флага отвергается. Обвязка сама передаёт точное
значение дочерним процессам и проверяет его при чтении их отчётов.

## Короткий контроль только холодного корня

```powershell
python -B -m isothermal_cx_model.scan_lambda --ionization-scale 0 --lambdas 7 --densities 1e15 --temperature-min .1 --temperature-max .15 --temperature-count 3 --j-min .7 --j-max .85 --j-count 4 --j-grid linear --max-starts 1 --no-show --output rr_lambda_cold_test
```

Для текущего источника даёт T=0.119194929 эВ, a=164.993436 см и
j_t=0.775561376. Это проверка отдельного участка, НЕ скан всех корней.

## Файлы

`roots_temperature_recombination.csv` — отдельная строка на каждый проверенный
корень; при постоянном CX в имени будет `constant`. Основные колонки:
lambda_sh, n0_cm3, T_eV, a_cm, theta, alpha, j_target, коэффициенты,
невязки и три ошибки балансов. Физические единицы — СГС, температура — эВ.
Формат прежний: разделитель `;`, UTF-8 с BOM.
Новая схема таблиц: format_version=2, ionization_scale в обеих таблицах,
root_kind=verified_stationary_atomic. Колонка recombined_fraction УДАЛЕНА:
1-j_t теперь net_particle_loss_fraction и может быть отрицательной.
Отдельно записаны recombination_count_per_inlet и ionization_count_per_inlet
(числа событий, нормированные на J0), а также energy_ionization_fraction
(интегральная потеря энергии на ионизацию, нормированная на W0).
На корне j_t-1 совпадает с числом ионизаций минус число рекомбинаций с точностью
невязки/квадратуры. Эти счётчики не являются взаимоисключающими долями частиц:
возможны повторные циклы. E_ion и энергетический счётчик учитывают I_D*k_ion,
без дополнительного 3T/2 или 5T и без двойного вычитания энергии связи при RR.
Старые пользовательские читатели колонки recombined_fraction нужно обновить.

`grid_temperature_recombination.csv` — отдельная строка на каждую завершённую
пару, даже если корни не найдены: n_roots, статусы пробных задач и попыток,
число допустимых узлов, кандидатов и стартов, численные остановки, наименьшая
выборочная норма. Норма в узле — не глобальный аналитический минимум.

`root_count.png` — число проверенных найденных корней в каждой физической паре.
`roots_temperature_recombination.png` — T(n0) и a(n0) для разных lambda.
Решения показаны отдельными точками, без предположения о связи ветвей между
соседними плотностями. Метки solution_id локальны для случая; номер корня
не является идентификатором непрерывной физической ветви или устойчивости.

`--no-show` сохраняет картинки без окон. `--no-plot` отключает только общие
картинки; индивидуальные карты всегда сохраняет исходный 2D-сканер.
Если корней нет ни в одной паре, графика T(n0),a(n0) не будет.

В `cases/pair_00001/attempt_001/result/` находятся прежние residuals.png,
residuals.npz, summary.json с историями стартов и root_..._profiles.npz.
Рядом — scan.log и точная команда запуска. Колонка case_report в обоих CSV
указывает относительный путь к этому summary.json. Глобальный solution_id
содержит и pair_..., и локальный root_..., поэтому строки разных пар уникальны.

Построитель графиков читает и прежние, и новые таблицы; при наличии метаданных
показывает множитель ионизации в легенде и не смешивает его разные значения:

```powershell
python -B -m isothermal_cx_model.plot_lambda_results rr_lambda_results/roots_temperature_recombination.csv --ionization-scale 0 --save rr_lambda_results/replotted.png --no-show
```

## Продолжение и защита исходных данных

Без `--resume` папка результатов должна отсутствовать или быть пустой.
После каждой завершённой пары обновляются CSV и progress.json. Прерывание
не требует повторять предыдущие завершённые пары.

Для продолжения повторите ТУ ЖЕ команду, добавив `--resume`. Нужно сохранить
параметры, физические и внутренние сетки, режимы и код проекта.
В том числе тот же --ionization-scale. manifest.json теперь имеет версию 2
и явно хранит этот множитель. Папки расчётов старой версии нельзя продолжить
новым кодом: выберите новую папку, старые данные остаются доступными.
Например, к первой команде с одной парой добавляется:

```powershell
python -B -m isothermal_cx_model.scan_lambda --ionization-scale 0 --lambdas 7 --densities 1e15 --no-show --output rr_lambda_test --resume
```

Незавершённая или ошибочная пара запускается заново в attempt_002 и т.д.;
частичный attempt_001 остаётся нетронутым. Продолжение посреди сетки одной
физической пары не реализовано. Общие CSV при resume пересобираются из
завершённых отчётов. Удалённые вручную картинки старых пар не восстанавливаются.

В manifest.json сохраняются параметры и SHA-256 исходных Python-файлов двух
пакетов. При изменении кода, сеток или источника resume отказывается смешивать
разные постановки: нужно выбрать новую папку. Проверка консервативна и
срабатывает даже на изменения кода, не влияющие на физику.
Версии внешних библиотек и бинарная среда этим хешем не фиксируются.

Дочерние расчёты читают копии исходного JSON и геометрии из папки результатов,
поэтому редактирование оригинального JSON во время большого скана не меняет
его следующие точки. Сам исходный проект, конфиг и геометрия не редактируются.
Не изменяйте source_config.json и geometry.json внутри папки результатов.

## Ограничения и коды завершения

Нулевое n_roots означает «из этой сетки и стартов корни не найдены», а не
«решений физически нет». Ошибка дочернего процесса, неполный отчёт или плохая
проверка не превращаются в нулевой корень: внешний скан останавливается,
сохраняя предыдущие пары и диагностику. После устранения причины можно resume,
если физика и код остались прежними; иначе нужна новая папка.

Даже ненулевое n_roots не доказывает полноты: нужны проверки разрешения сетки
и числа стартов, локальные карты и сравнение уточнённых корней.
Новые физические процессы здесь не добавляются; это прежняя изотермическая
атомная модель с заданными нейтралами, Case A RR и опциональной ионизацией;
трёхчастичная рекомбинация, молекулы и перенос излучения не добавлены.

Внешний код 0 означает «все пары завершены», в том числе если найдено 0 корней;
2 — ошибка входных данных или дочернего расчёта; 130 — прерывание пользователем.
Код 1 дочернего 2D-сканера без найденных корней является нормальным результатом
для одной пары, если его отчёт полностью завершён.

Тесты: `python -B -m unittest discover -s tests -p test_parameter_scan.py -v`.
Ионизация: `python -B -m unittest discover -s tests -p test_atomic_batch.py -v`.
