# Решатель согласованных стационарных состояний с рекомбинацией

Первая версия локального/мультистартового поиска по theta и j_t. Она использует
проверенный solver_recombination.solve_trial, но НЕ требует патча с картой
невязок. Старые scan_neutral, scan_lambda и plot_profiles не изменяются и
автоматически не переходят на новый решатель. Запускать RR-задачу следует новой
командой run_recombination.

## Запуск из корня проекта

Физические параметры источника и масштабы читаются из cx_config.json.
Каждый --guess задаёт только начальное приближение: температура в эВ и j_t.
Исходный JSON никогда не редактируется. Контрольный холодный случай:

```powershell
python -B -m isothermal_cx_model.run_recombination --density 1e15 --lambda-sh 7 --guess 0.13 0.8 --no-show --output rr_cold_root
```

Три разных начальных приближения для того же набора физических параметров:

```powershell
python -B -m isothermal_cx_model.run_recombination --density 1e15 --lambda-sh 7 --guess 0.13 0.8 --guess 15 0.99999997 --guess 80 0.9999999999 --no-show --output rr_three_starts
```

Не переносите найденные ранее T,a,j_t на другие n0 или lambda без нового
расчёта. Текущий JSON содержит n0=1e14 и lambda_sh=8; они НЕ меняются на значения
контрольного примера по умолчанию. Для нового набора следует задать подходящие
начальные приближения или использовать несколько стартов.

Параметры --geometry/--K и --inlet-momentum работают как в прежних командах.
По умолчанию: квадратичная площадь K=500, кинетический вход, температурный
k_cx(T,0), возбуждение и радиационная рекомбинация полностью включены.
Флаги --excitation-scale и --rr-scale позволяют менять общие множители от 0
до 1. При RR=0 коэффициенты рекомбинации не вызываются, а j_t=1 поддерживается
точно как граничное значение. --cx-mode constant сохраняет постоянный k_cx.

## Что решается

При заданных theta,j_t пробный интегратор выполняет выходные условия Бома и
omega_t=lambda_sh*theta*j_t, затем находит alpha по omega(alpha)=1.
Теперь подбираются theta,j_t, для которых одновременно

    R_J = j(alpha)-1 = 0
    R_M = mu(alpha)-G(alpha) = 0.

Рабочие координаты поиска — x=(log(theta),log(j_t)). Это сохраняет положительность
и не вырождает производную по потоку вблизи j_t=1, как произошло бы при логите.
Для численной корректировки используются f=(log(j(alpha)),log(mu(alpha)/G(alpha))).
Нули f совпадают с нулями исходных невязок; исходные R_J,R_M также проверяются
и сохраняются. Сам IVP и его физические уравнения не меняются.

Шаг Ньютона ограничен в логарифмических координатах, с уменьшением шага до
допустимого IVP и уменьшения невязки; при необходимости пробуется градиентное
направление. Недопустимые интегрирования НЕ заменяются нулём или искусственным
штрафом. Двусторонние/односторонние разности используются только там, где
определены настоящие невязки. Положительный R_J и отрицательный целевой звуковой
запас пробного входа не отбрасываются до согласования корня.

После предварительной сходимости выполняется новая корректировка с меньшими
допусками и меньшим максимальным шагом IVP. Затем считаются полноценные профили,
обе входные невязки, звуковой запас и интегральные балансы частиц, импульса и
энергии. Только после этого результат получает верхнеуровневый status=converged.
Флаг успешности внешнего оптимизатора не используется как критерий решения.

## Python API

```python
outcome = solve_stationary(theta_guess, j_guess, beta, D, lambda_sh, geometry,
    E_exc=E, rr=rr, inlet_momentum=inlet)
if outcome['status'] == 'converged':
    solution = outcome['solution']
    profiles = compute_stationary_profiles(solution, parameters)

solutions, diagnostic = find_stationary_solutions(
    [(theta_1, j_1), (theta_2, j_2)], beta, D, lambda_sh, geometry,
    E_exc=E, rr=rr, inlet_momentum=inlet)
```

Функции поиска — в stationary_recombination.py; новые профили и рисунки —
в profiles_recombination.py. В Python API температура начального приближения
безразмерная theta, а в CLI --guess температура в эВ.

outcome['solution'] появляется только при проверенной сходимости. Этот объект
сохраняет model=rr_trial и status=energy_matched исходного IVP, но дополнительно
содержит stationary_verified=True, verification и balances. Для согласованности
следует проверять верхнеуровневый outcome['status'], не только IVP-статус.

Близкие численные копии объединяются по theta,j_t,alpha с заданным dedup_tol.
Сортировка и root_001/root_002/... назначаются по theta, а не по метке monotone:
несколько разных корней могут иметь одинаковую форму профиля. dedup_tol является
численным разрешением, а не доказательством тождества двух математических ветвей.

## Область и точность поиска

По умолчанию используются residual_tol=1e-9, max_iterations=40, 4000 точек
выходного профиля. Поиск IVP: rtol=1e-9, atol=1e-11, max_step=.02. Проверка
ужесточает допуски как минимум до 1e-11 и 1e-13 и уменьшает max_step вдвое.
Допуск log-невязок на проверочной стадии не больше 1e-11. Нормированная ошибка
каждого интегрального баланса не должна превышать balance_tol=5e-6.

--points меняет число выходных точек и качество квадратур, не шаг адаптивного
интегратора. --residual-tol, --balance-tol, --iterations задают доступные настройки.
В API также можно менять rtol,atol,max_step. Очень малая потеря 1-j_t может
потребовать более строгой абсолютной точности; сравнивайте её с невязкой R_J
и с particle_loss_integral, а не только с округлённым отображением j_t.

При включённой RR CLI ограничивает T областью опубликованных формул (3 K--1e9 K).
Собственное окно задаётся парой --temperature-min/--temperature-max в эВ;
при выходе за область коэффициентов IVP всё равно не считается допустимым.
--j-min=1e-12 — нижняя граница численного окна, НЕ физический критерий полного
детачмента. Увеличивать физическую достоверность простым расширением этих границ
нельзя. Границу lambda*theta<1 прежней модели здесь не применяют: условие теперь
lambda*theta*j_t<1 и проверяется пробным интегратором.

## Результаты и неуспехи

Выбирайте новую или пустую папку --output. Существующие результаты не
перезаписываются: это предотвращает смешение старых и новых файлов корней.

- solutions.json: параметры, начальные приближения, режимы, проверенные корни,
  коэффициенты процессов в корнях, невязки, балансы и диагностика всех попыток;
- root_001_profiles.npz и т.д.: численные профили без pickle, включая переменный
  J, n,u,W и q_e в СГС, а также безразмерные профили;
- profiles.png: пять панелей J/J0, W/W0, q_e, u/c_s, n/n_star.

--no-show сохраняет рисунок без окна, --no-plot не создаёт рисунок. Код завершения
0 означает хотя бы один проверенный корень; 1 — ни один старт не дал проверенного
корня; 2 — неправильные аргументы. Даже при коде 1 сохраняется диагностика.

Причины неуспеха: initial_outside_search_bounds, invalid_initial_trial,
iteration_limit, jacobian_unavailable, ill_conditioned_jacobian,
line_search_failed, verification_..., balance_check_failed и
inlet_not_strictly_subsonic. Численные/физические статусы IVP учитываются отдельно
в invalid_trials. Это не доказательства отсутствия решений. При неустранимом
локальном неуспехе нужны другие старты, область поиска или отдельное исследование
почти вырожденного корня; искусственных корней алгоритм не создаёт.

НЕ используйте старую profiles.compute_profiles: она предполагает J=J0.
Новый compute_stationary_profiles проверяет согласованность масштабов и
использует J(z)=J0*j(z) в плотности и конвективной энергии.

## Проверенный контрольный случай

n0=1e15 см^-3, lambda_sh=7, K=500, текущий источник JSON, CX(T,0), возбуждение
и RR полностью включены. Три старта из примера дали:

| Корень | T, эВ | a, см | j_t |
| --- | --- | --- | --- |
| root_001 | 0.11919492897 | 164.99343626 | 0.775561375634 |
| root_002 | 14.936348171 | 182.79306254 | 0.999999966082 |
| root_003 | 77.821840327 | 183.90708530 | 0.999999999909 |

Обе входные невязки каждого корня меньше 1e-10. На 4000 точках ошибки
интегральных балансов не превышают 1.1e-7 от соответствующих масштабов потоков.
Этот набор не доказывает, что других корней нет, и не устанавливает устойчивость.

18 новых тестов проходят: независимый аналитический эталон при A=const без RR,
точный граничный j_t=1, холодный и горячий корни, реальные три старта,
повторная проверка и её отказ, интегральные балансы, одинаковые monotone-метки,
дубликаты, численные неуспехи, профили с переменным J, JSON/NPZ и защита результатов.
Один исходный аналитический тест в test_kinetic_inlet падает и до изменений
при текущем JSON; этот решатель его не меняет. Модуль карты невязок для тестов
и работы нового решателя не требуется.

## Физические ограничения

Изотермичность, заданный газ, низкоплотностная Case-A рекомбинация, отсутствие
ионизации, трёхчастичной рекомбинации и переноса излучения сохранены. Особенно
на холодной плотной ветви наличие точного численного корня не подтверждает
применимость этих приближений к эксперименту ГДЛ.
