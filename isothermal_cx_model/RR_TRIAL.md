# Пробное интегрирование с радиационной рекомбинацией

Единственная реализация находится в transport.py; старая обёртка удалена.
Ниже описан предел без ионизации (ionization=(0,0) в низкоуровневом API).
CLI trial_example по умолчанию включает ионизацию; для этого предела задайте
--ionization-scale 0. Полная атомарная модель описана в ATOMIC_TRIAL.md.

Это только следующий небольшой этап: заданные theta и j_target -> профиль,
граница alpha и две входные невязки. Подбора theta и j_target ещё НЕТ.
Исследование числа решений и точки слияния ветвей в этот этап не входит.

Сохраняются T_i=T_e=const, заданный фон нейтралов и общая магнитная геометрия.
Добавлена только радиационная рекомбинация Case A. Трёхчастичная рекомбинация,
ионизация, перенос излучения и движение новых нейтралов не включены. Поэтому
успешное интегрирование очень холодного профиля не подтверждает применимость
этих физических приближений.

## Функция

```python
state = solve_trial(theta, j_target, beta, D, lambda_sh, geometry,
                    E_exc=E, rr=rr, inlet_momentum=inlet)
```

D и E_exc — числа или функции theta. rr — пара (R,Q) либо одна функция theta,
возвращающая пару. Физически согласованную пару создаёт
make_rr_coefficients(parameters, scale=eta_RR). Общий множитель eta_RR от 0 до 1
применяется сразу к R и Q. При eta_RR=0 температурные формулы RR не вызываются.

    R(theta) = eta_RR * L*n_star*alpha_RR(T)/u_star
    Q(theta) = eta_RR * L*n_star*C_RR(T)/(u_star*T_star_erg)

Температура в атомных коэффициентах задаётся в эВ. C_RR содержит только потерю
кинетической энергии электронов. Энергия связи не вычитается из W повторно.
Обновлённый recombination.py сохраняет прежние функции и добавляет фабрику
безразмерных коэффициентов и отдельный подкласс ValueError для диапазона T.

## Уравнения и координата

Код интегрирует по g=z/L, не по xi. Поэтому в RHS НЕТ множителя (1-alpha).

    b = sqrt(8*beta*theta)
    Delta = sqrt(mu**2 - b**2*j**2)
    H = mu + Delta
    A = A(z)/A_star
    Phi = H**2/(16*beta**2*theta**2*A)

    dj/dg = -R*Phi
    dmu/dg = -0.5*(d ln B/dg)*H - D*j - R*j*H/(4*beta*theta*A)
    domega/dg = -D*(5*mu+Delta)/(8*beta) - E_exc*H/(4*beta*theta)
                - R*j**2/(2*beta*A) - (1.5*R*theta+Q)*Phi

Условия на приёмнике g=1:

    j=j_target; mu=b*j_target; omega=lambda_sh*theta*j_target.

Для некритической дозвуковой ветви проверяется

    D > -(b/2)*(d ln B/dg)_wall + R*b*j_target/(4*beta*theta*A_wall).

Здесь производная F=mu-b*j при g=1 должна быть отрицательна. Равенство получает
статус critical_wall_unresolved, а не утверждение об отсутствии решения.
Энергетическое условие: lambda_sh*theta*j_target < 1; старое ограничение
lambda_sh*theta < 1 здесь НЕ используется.

От приёмника интегрируем назад до omega=1. Эта точка задаёт alpha. Затем:

    R_J = j(alpha)-1
    R_M = mu(alpha)-G(alpha), где G=M_kin(a)/M0 или явно заданная функция.

Положительный R_J, в частности j(alpha)>1, НЕ отбрасывается. Это допустимый
пробный профиль, нужный для будущего поиска совместного нуля невязок.
Отрицательный целевой звуковой запас на входе тоже не уничтожает пробную
невязку. Он должен будет проверяться у окончательно согласованного корня.

## Результат и статусы

`status='energy_matched'` означает только omega(alpha)=1, а НЕ решение всей
граничной задачи. Для полного решения нужны одновременно R_J=0 и R_M=0.

После достижения omega=1 возвращаются одинаковые по размеру массивы:

- g, xi=(g-alpha)/(1-alpha), j, mu, omega;
- u_over_u_star, u_over_cs, n_over_n_star, A_over_A_star;
- Aq_e_over_W0 = omega-j*(v**2/(2*beta)+5*theta).

Порядок точек: от alpha до 1. Размерные профили получают так:

```python
z_cm = p['L_cm'] * state['g']
n_cm3 = p['n_star_cm3'] * state['n_over_n_star']
u_cm_s = p['U_star_cm_per_s'] * state['u_over_u_star']
J_per_s = p['J0_per_s'] * state['j']
W_erg_s = p['W0_erg_per_s'] * state['omega']
A_cm2 = p['A0_cm2'] * state['A_over_A_star']
q_e_erg_cm2_s = p['W0_erg_per_s'] * state['Aq_e_over_W0'] / A_cm2
```

НЕ передавайте пробный RR-профиль старой функции profiles.compute_profiles:
она предполагает J=J0. Добавлена явная защита от такого использования, чтобы
не получить молча неверную плотность. Старые решатели и старые профили работают
по-прежнему; глобальные сканы автоматически на новый решатель не переводятся.

Другие статусы:

- energy_temperature_limit — энергия на приёмнике >= входной;
- inadmissible_wall — неправильное направление выхода с дозвуковой стороны;
- critical_wall_unresolved — критический звуковой старт;
- recombination_temperature_out_of_range — вне области аппроксимаций RR;
- sonic_return — возврат к звуку раньше достижения входной энергии;
- geometry_limit — входная энергия не достигнута в заданной геометрии;
- kinetic_inlet_outside_domain — найденная граница вне области кинетического
  входа; массивы и R_J сохраняются, а R_M остаётся NaN;
- integration_failed — численная ошибка, не доказательство физической
  невозможности решения;
- nonpositive_particle_flux, sonic_resolution_limited,
  profile_validation_failed, boundary_outside_open_domain — дополнительные
  проверки допустимости или численного разрешения.

Где невязка не определена, возвращается NaN, а не искусственный ноль. Ошибки
входных аргументов или программирования вызывают исключения, не маскируются
под физическое отсутствие решений. Для интегрированных неуспешных попыток
также имеются g_stop и last_state; при ошибке до интеграции этих полей нет.

## Простой запуск без поиска параметров

```powershell
python -B -m isothermal_cx_model.trial_example --temperature 10 --j-target 0.5 --ionization-scale 0
```

Это пробное интегрирование, а не подбор стационарного решения.
Параметры источника читаются из simple_cx_model/cx_config.json.
Граница a определяется условием энергии; входные невязки могут быть ненулевыми.

## Проверки

```powershell
python -B -m unittest discover -s tests -p test_transport_limits.py -v
python -B -m unittest discover -s tests -v
```

Проверяются коэффициенты RR, независимый аналитический предел A=const,
интегральные балансы, допустимость профилей и статусы неуспешных попыток.
Тесты сравнения с удалённым решателем и его старых интерфейсов исключены.
