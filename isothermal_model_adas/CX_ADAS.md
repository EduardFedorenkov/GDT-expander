# Коэффициенты перезарядки CCD96_D

`cx_adas.py` — самостоятельный слой коэффициентов, аналогичный прежнему `cx.py`.
Коэффициент **подключён** к источникам импульса/энергии, граничной проверке
и балансам через необязательный аргумент D в transport/stationary.
Загрузка таблицы происходит при первом активном обращении, а не при импорте.

```python
from isothermal_model_adas.cx_adas import k_cx, D_cx, make_D

k = k_cx(5.0)                  # cm^3/s; температура в eV
k = k_cx(5.0, u_z_cms=0.0)    # прежний нулевой аргумент u допустим
D = D_cx(theta, p, n0_cm3=1e14)
D_of_theta = make_D(p, mode="temperature", n0_cm3=1e14)
D = D_of_theta(theta)
```

Требуемые масштабы в `p`: `L_cm`, `U_star_cm_per_s`, `T_star_eV`.
Нейтральная плотность задаётся аргументом `n0_cm3` либо одноимённым полем `p`.
В конфиге новой модели это поле теперь читается; пример содержит 1e14 cm^-3.
При отсутствии поля n0=0 (совместимость со старым конфигом). CLI --density
переопределяет его, а --density 0 выключает CX без загрузки CCD.

    D(theta) = L*n0/u_star * CCD(T_star_eV*theta)

В отличие от старого `make_D`, по умолчанию выбран режим **temperature**:
это модуль ADAS, поэтому значение по умолчанию действительно использует CCD.
Для прежнего режима постоянного коэффициента:

```python
p["k_cx_cm3_per_s"] = 1e-8
D_const = make_D(p, mode="constant", n0_cm3=1e14)
```

`constant` использует заданное число, **не** CCD при опорной температуре.
Этот режим и выключение через `n0=0` не требуют файла ADAS. Фабрика сохраняет
копию нужных масштабов: изменение `p` после создания функции её не меняет.

## Интерполяция и проверки

Файл по умолчанию: `processes_data/ccd96_d.dat`. Для другого экземпляра:

```python
from isothermal_model_adas.cx_adas import ADASCX
data = ADASCX(path)
k = k_cx([1., 5., 20.], data=data)
```

Reader проверяет DEUTERIUM, единственный блок, единицы cm^3/s, порядок осей,
число коэффициентов и **точное отсутствие зависимости от электронной плотности**.
Если появится действительно плотностно-зависимый CCD, он будет отклонён,
а не молча сведён к первому столбцу.

Линейная интерполяция в log10(T), log10(k). Диапазон данного файла:
номинальные 0.2–10000 eV; экстраполяция запрещена. Допуск 1e-8 по log10(T)
учитывает только округление напечатанных концов сетки.
`k_cx` и `D_cx` принимают скаляры/массивы температуры; n0 и масштабы скалярные.
Не вводится искусственная зависимость от n_e или n_star.

## Физические ограничения

Здесь явно принято **k_model(T)=CCD(T)**. Не доказано совпадение условий
усреднения CCD с прежней моделью холодных неподвижных нейтралов. Температуры
иона/нейтрала и относительный дрейф не являются независимыми аргументами CCD.
Поэтому ненулевой `u_z_cms` вызывает ValueError: он не игнорируется и не
переводится произвольным образом в эффективную температуру.

В отличие от старого `cx.py`, функции `sigma_cx_D` нет: сечение нельзя
восстановить непосредственно из этого набора тепловых коэффициентов.
Для D+ + D -> D + D+ CX не создаёт суммарной потери ионов. Он даёт вклад
в импульс и энергию, но не дополнительный ACD.

Частотный коэффициент CCD сам по себе не определяет точные транспортные
моменты; прежнее использование одного k для потерь импульса и энергии
останется отдельным оценочным приближением.

Источники: https://open.adas.ac.uk/element/detail/adf11/ccd96/ccd96_d.dat
и https://www.adas.ac.uk/man/appxa-14.pdf . Исходный .dat не изменяется и не
входит в патч: файл уже находится в проекте у пользователя.

Только вывод коэффициентов, без решения плазменной задачи:

```powershell
python -B -m isothermal_model_adas.cx_adas --temperatures .2 1 5 20 100
```

Тесты именно коэффициентов, без запуска IVP/BVP:

```powershell
python -B -m unittest discover -s isothermal_model_adas/tests -p test_cx_adas.py -v
```
