# Графики из сохранённых ADAS-таблиц

`plot_lambda_results.py` читает roots.csv и строит три графика на одном
изображении: **T(n0), a(n0), j_t(n0)**. Модель и коэффициенты ADAS не
импортируются и не вычисляются. Достаточно NumPy/Matplotlib; SciPy нужен
только для опциональных плавных линий. CSV и JSON не перезаписываются.

## Использование из корня проекта

```powershell
python -B -m isothermal_model_adas.plot_lambda_results adas_lambda_001/roots.csv --save adas_lambda_001/roots_replot.png --no-show
```

Вместо CSV можно передать папку результатов — автоматически выбирается
roots.csv. При наличии рядом grid.csv и manifest.json они читаются как
таблица завершённых пар и план плотностей скана.

Фильтрация по значениям lambda и логарифмическая шкала температуры:

```powershell
python -B -m isothermal_model_adas.plot_lambda_results adas_lambda_001 --lambdas 7 8 --temperature-scale log --save adas_lambda_001/selected_roots.png --no-show
```

По умолчанию отображаются только рассчитанные точки. Для привычных плавных
визуальных линий, как в старом рисователе:

```powershell
python -B -m isothermal_model_adas.plot_lambda_results adas_lambda_001 --connect --save adas_lambda_001/root_guides.png --no-show
```

Линии — **направляющие по температурному рангу**, не физическое продолжение
ветвей, не дополнительные решения и не результат анализа устойчивости.
Они строятся PCHIP по log10(n0), без экстраполяции и с сохранением исходных узлов.

## Пропуски и несколько решений

Все сохранённые корни показываются отдельно, включая несколько решений
при одной плотности и j_t>1. Значение j_t=1 отмечено горизонтальным пунктиром.
Цвет различает lambda; при смешанных физических настройках отдельными группами
показываются также rr_scale, ionization_scale, excitation_scale и inlet_momentum.
Локальные root_NNN не используются как сквозные номера физических ветвей.

Для --connect нужна таблица grid.csv: соединять только имеющиеся корни,
игнорируя плотности без найденных корней, было бы неверно. Направляющие
обрываются при нулевом числе корней, изменении их числа, неоднозначном
температурном ранге и известных пропусках запланированных расчётов.

Если есть manifest.json, используются все запланированные плотности,
включая ещё не рассчитанные. Без manifest известен только набор плотностей
из grid.csv: полностью отсутствующий в нём шаг невозможно восстановить.
Поэтому линии в любом случае остаются лишь визуальной подсказкой.

Нулевой n0 — контрольная точка: показывается на symlog-оси, но в
логарифмическую интерполяцию не включается. При отсутствии найденных корней
строится изображение с пояснением, а не фиктивные нулевые T/a/j_t.

## Флаги

- `--lambdas ...`: выбрать значения lambda_sh; по умолчанию все сохранённые.
- `--temperature-scale linear|log`: масштаб T, по умолчанию linear как в старом рисователе.
- `--connect`: добавить направляющие; требует grid.csv.
- `--points-only`: только точки (также поведение по умолчанию).
- `--grid PATH`, `--manifest PATH`: явно указать сопутствующие файлы.
- `--no-grid`: не читать соседний grid.csv; несовместим с --connect по смыслу.
- `--save PATH`: сохранить PNG/PDF/SVG в существующую папку.
- `--overwrite`: разрешить замену указанного изображения; без него существующий
  файл не затирается. Пути входных CSV/manifest защищены даже с этим флагом.
- `--no-show`: сохранить без интерактивного окна; без --save файл не создаётся.

CSV: разделитель `;`, UTF-8 с BOM или без него. Обязательны lambda_sh, n0_cm3,
T_eV, a_cm, j_target. Неизвестный j_target не подменяется единицей.
Проверяются конечность/знаки чисел, дубликаты и согласованность числа корней
между таблицами. Это проверка таблицы, не повторная верификация краевой задачи.
Если файлы читаются во время обновления CSV сканером, они могут временно не
совпасть: следует повторить построение после завершения записи пары.

## Python API

```python
from isothermal_model_adas.plot_lambda_results import (
    load_roots_csv, load_grid_csv, load_density_plan, plot_roots,
)

rows = load_roots_csv('adas_lambda_001/roots.csv')
grid = load_grid_csv('adas_lambda_001/grid.csv')
plan = load_density_plan('adas_lambda_001/manifest.json')
fig, axes = plot_roots(rows, lambdas=[8.], grid=grid, density_values=plan,
                       connect=True, temperature_scale='log')
fig.savefig('adas_lambda_001/lambda8.png', dpi=180)
```

plot_roots возвращает Figure и массив из трёх осей, сам не читает файлы,
не сохраняет и не показывает окно. Входные словари не изменяются.

## Установка и незавершённые сканы

Новый Python-файл изменяет строгий отпечаток кода пакетного скана. Не следует
применять патч в код работающего scan_lambda: следующая проверка версий
остановит его, а старый --resume с новой версией кода будет отклонён.

Чтобы посмотреть результаты во время такого расчёта, можно запустить
сам plot_lambda_results.py из внешней папки обычной командой Python, передав
путь к CSV: скрипт не использует относительные импорты и не требует установки
в пакет. Для новых сканов применять патч до их начала. Ранее сохранённые
данные остаются пригодны для независимого построения графиков.

Тесты только CSV/изображений, без физического расчёта:

```powershell
python -B -m unittest isothermal_model_adas.tests.test_plot_lambda_results -v
```
