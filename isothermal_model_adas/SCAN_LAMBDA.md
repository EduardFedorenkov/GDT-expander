# Перебор lambda_sh и плотности нейтралов в ADAS-модели

`scan_lambda.py` запускает существующий `scan_stationary.py` для каждой пары
`(lambda_sh,n0)`. Уравнения, коэффициенты, граничные условия и локальный
корректор не меняются. Для каждой пары строится новая трёхмерная карта
`(theta,j_t,alpha)` и выполняется независимый автоматический поиск.
Это не продолжение одной заранее выбранной ветви.

Пакетная логика вынесена в `parameter_scan.py`. Флагов выбора модели
перезарядки нет: используется только CCD(T).

## Начать с проверки объёма

Из корня проекта:

```powershell
python -B -m isothermal_model_adas.scan_lambda --lambdas 8 --densities 1e13 --temperature-count 4 --j-count 4 --alpha-count 3 --dry-run --no-show
```

Это одна физическая пара и 48 пробных интегрирований карты, плюс неизвестное
заранее число интегрирований корректора. При dry-run не интегрируется плазма
и не создаются файлы; конфиг и активные таблицы проверяются.

Без параметров задана сетка 5 значений lambda=5..9 и 7 плотностей
1e12..1e15 см^-3. Внутренняя сетка 16*16*7 даёт **62720 пробных IVP**,
не считая уточнений. Это большой расчёт: перед запуском используйте dry-run.

Температура по умолчанию .2..150 эВ: верхний предел соответствует принятому
для текущей задачи ограничению. Его можно явно изменить флагом
`--temperature-max`; выход за диапазоны активных таблиц запрещён.

## Небольшой пакет и продолжение

Пример четырёх независимых расчётов с более редкой внутренней сеткой:

```powershell
python -B -m isothermal_model_adas.scan_lambda --lambdas 7 8 --densities 1e13 2e13 --temperature-count 8 --j-count 8 --alpha-count 5 --max-starts 12 --no-show --output adas_lambda_001
```

Это пример интерфейса, а не проверенная достаточная сетка. Во время разработки
нового пакетного кода физический скан не запускался. Для поиска узких областей
сходимости нужны сгущение/расширение сетки и несколько начальных приближений.

После прерывания повторить **ту же команду** с теми же входными параметрами
и добавленным `--resume`:

```powershell
python -B -m isothermal_model_adas.scan_lambda --lambdas 7 8 --densities 1e13 2e13 --temperature-count 8 --j-count 8 --alpha-count 5 --max-starts 12 --no-show --output adas_lambda_001 --resume
```

Уже завершённые пары не запускаются повторно. Незавершённая пара считается
незавершённой даже при наличии сохранённых промежуточных корней: она
пересчитывается в новой папке attempt_NNN, а старая попытка сохраняется.
Это resume **по физическим парам**, не по итерациям отдельного корректора.

Нельзя смешивать версии кода, ADAS-таблиц, конфига, геометрии, сеток и
численных настроек: при несовпадении продолжение отклоняется. После изменения
модели или настроек нужно выбрать новую папку результатов. Предыдущие
результаты и их исходные данные не редактируются.

## Параметры

- `--lambdas ...` либо `--lambda-min/max/count`: явный список или линейная
  сетка положительного lambda_sh. Для count=1 границы должны совпадать.
- `--densities ...` либо `--n0-min/max/count`: нейтральная плотность в см^-3,
  явный список или логарифмическая сетка. Ноль разрешён только в явном списке
  как контроль без нейтралов. Повторяющиеся значения объединяются, список сортируется.
- `--config`, `--geometry` или `--K`: тот же конфиг и геометрия, что у
  одиночного сканера. CLI не редактирует JSON; lambda/n0 переопределяются
  отдельно для каждой пары.
- `--temperature-min/max/count`, `--j-min/max/count`, `--j-grid`,
  `--alpha-min/max/count`: сетка каждой карты. Положительные j_t>1 допустимы.
- `--max-starts`, `--separation`, `--iterations`, `--points`, `--map-points`,
  `--residual-tol`, `--balance-tol`, `--dedup-tol`, `--rtol`, `--atol`,
  `--max-step`: передаются одиночному сканеру без изменения.
- `--rr-scale`, `--ionization-scale`, `--excitation-scale`, `--inlet-momentum`:
  те же физические замыкания, что в SCAN_STATIONARY.md.
- `--guess T_EV J_TARGET ALPHA`: дополнительный старт в каждой паре;
  повторяемый, не обязательный. Он не заменяет автоматическую карту.
- `--alpha-slice INDEX`, `--j-axis`: настройки карт каждой пары.
- `--no-case-plots`: не создавать PNG карт и профилей в отдельных расчётах.
- `--no-plot`: не создавать общие графики пакета; для отключения всех PNG
  нужно также указать `--no-case-plots`.
- `--no-show`: без интерактивных окон. Дочерние расчёты всегда без окон.
- `--output`: новая/пустая папка, либо существующая папка этого пакета с --resume.

## Что сохраняется

```text
output/
  manifest.json, source_config.json, geometry.json
  checkpoint.json, status.json
  roots.csv, grid.csv
  root_count.png, roots.png
  cases/L000_N000/
    attempt_001.log
    attempt_001/summary.json, residuals.npz, ...профили и графики...
```

`manifest.json` хранит сетки, настройки, геометрию, SHA256 исходников и
активных ADAS-файлов, версии Python/NumPy/SciPy. Конфиг и геометрия фиксируются
для всего пакета; параметры конкретной пары записаны в её summary.json.
Сырые ADAS .dat не копируются в результаты.

`checkpoint.json` содержит только успешно завершённые и проверенные пары,
контрольные суммы их отчётов, NPZ-карт и профилей. `status.json` показывает
стадию running/complete/interrupted/failed и текущую пару.

CSV имеют разделитель `;` и кодировку UTF-8 с BOM. Они атомарно обновляются
после каждой завершённой пары и могут быть восстановлены из отчётов при resume:

- `roots.csv`: все проверенные корни, lambda/n0, T, a, alpha, j_t,
  D, рождение/убыль частиц, энергетические вклады, невязки, ошибки бюджетов
  и пути к полным отчётам/профилям. Энергетические вклады нормированы на W0;
  эффективный рекомбинационный вклад может быть отрицательным.
- `grid.csv`: число найденных корней в каждой завершённой паре, число допустимых
  проб и стартов, неудачные уточнения, минимальная выборочная невязка и статусы.

Формат manifest/checkpoint/status — версия 1 с model=isothermal_adas и
kind=lambda_neutral_scan в manifest. Вложенные отчёты — существующий
stationary_scan_3d, версия 2. Старые Case-A CSV/отчёты не считаются совместимыми.

## Интерпретация и ошибки

Перед агрегированием проверяются стадия завершения, параметры и происхождение
расчёта, граничные невязки, независимые бюджеты, нормировки, согласованность
ионизационного расхода энергии с рождением частиц, наличие карты и профилей.
Q_eff не обязан быть положительным, ионизация допускает j_t>1.
Один только код завершения дочернего процесса не считается результатом.
Ошибка/прерывание не превращаются в строку «0 корней».

root_count.png показывает **число найденных корней**, не границу существования
или детачмента. roots.png — точки T(n0) и a(n0), цветом обозначен lambda.
Точки не соединяются в физические ветви автоматически. Локальные root_NNN
и составные ID не означают устойчивости или принадлежности непрерывной ветви.

Код завершения пакета 0 означает, что все пары обработаны, даже если ни в
одной не найдено корней. Ошибка останавливает пакет; завершённые пары остаются.
Обычный Ctrl+C завершает текущий дочерний процесс и сохраняет checkpoint.
При жёсткой остановке приложения status может остаться running; для resume
надо предварительно убедиться, что старый дочерний расчёт уже не работает.

## Тесты без физического скана

```powershell
python -B -m unittest isothermal_model_adas.tests.test_scan_lambda -v
```

Проверяются CSV, несколько пар, resume, повтор незавершённой попытки,
изменённые входные данные/версии, повреждённые отчёты и профили, нулевая
нейтральная плотность, отображение графиков и запуск вспомогательного процесса.
Физические интегрирования и корни в этих проверках заменены тестовыми данными.
